[다크 팩토리와 루프](/blog/dark-factories-and-the-loop)에서 우리는 자율성이란 아키텍처가 아니라 하나의 조절 장치라고 주장했다. 동일한 하네스, 동일한 hats, 동일한 백프레셔 — 단지 얼마나 주의 깊게 지켜볼지를 선택할 뿐이다. 그것이 원칙이었다. 이번 주, 우리는 그 조절 장치의 양 끝단을 출시했다.

**빠른 모드**는 완전한 hat 규율을 갖추고 간단한 작업을 처리한다. **자동 조종**은 전략적 인간 체크포인트를 갖추고 자율적인 기능 배포를 처리한다. 기존의 `/elaborate` 및 `/execute` 수동 흐름과 함께, AI-DLC는 이제 30초짜리 수정부터 무인 다중 Unit 빌드까지 전체 스펙트럼을 아우른다.

## 기존 `/quick`의 문제점

원래의 `/quick` 스킬은 우회로였다. hats를 건너뛰고, 플래너/빌더/리뷰어 사이클을 건너뛰고, 워크플로우 전체를 건너뛰었다. 그 명분은 속도였다. 사소한 변경에 왜 전체 기계를 돌려야 하는가?

답은 결국 이것이었다: 그 기계가 바로 결과물을 좋게 만드는 것이기 때문이다.

파일 하나의 오타 수정조차도 인접한 문제를 잡아내는 리뷰어 hat의 혜택을 받는다. 설정 변경조차도 원자적으로 커밋하는 빌더 hat의 혜택을 받는다. 원래의 `/quick`은 품질을 속도와 맞바꿨고, 그 거래는 가치가 없었다. 품질을 중시하는 사용자들은 빌드하는 것보다 명세하는 데 더 오래 걸리는 작업을 포함해 모든 것에 `/elaborate`를 사용했다.

## 빠른 모드, 재설계

새로운 `/quick`은 선택적 워크플로우 이름과 작업 설명을 받는다: `/quick tdd fix the validator`. 이 명령은 `workflows.yml`에서 해당 워크플로우의 hat 시퀀스를 읽고 완전한 인메모리 hat 루프를 실행한다.

핵심 설계 결정 사항은 다음과 같다:

**지능적 라우팅.** 사용자가 슬래시 명령 없이 작업을 설명하면, 시스템은 휴리스틱 신호 — 수정된 파일, 변경의 성격, 테스트 필요 여부, 설계 결정 포함 여부 — 를 사용해 범위를 평가한다. 그런 다음 `/quick` 또는 `/elaborate`를 제안한다. 사용자는 항상 확인한다. 시스템은 권고할 뿐, 결정하지 않는다.

**임시 아티팩트.** 빠른 모드는 기존 훅 시스템이 hat 컨텍스트를 주입할 수 있도록 최소한의 Intent 상태를 담은 `.ai-dlc/quick/` 디렉토리를 생성한다. 이 디렉토리는 완료 후 정리되며 커밋되지 않는다. 훅 인프라는 해당 작업이 "빠른" 것인지 알지도 신경 쓰지도 않는다 — Intent 상태를 보고 정상적으로 동작할 뿐이다. 특수 케이스도, 우회로도 없다.

**빌더/리뷰어 사이클.** 빌더 hat은 사이클당 하나의 커밋을 생성한다. 리뷰어가 거부하면 작업은 빌더에게 되돌아간다. 세 번의 사이클이 실패하면 빠른 모드는 중단되고 `/elaborate`를 권고한다 — 그 작업은 사실 사소한 것이 아니었던 것이다. 이것은 사전 추정이 아닌 실행을 통한 범위 감지다.

**배포 전 검토.** 모든 빠른 모드 PR은 PR 생성 전에 `/ai-dlc:review`를 거친다. 리뷰 스킬은 외부 CI나 리뷰 봇이 작업을 보기 전에 로컬에서 문제를 잡아낸다. 출구에서도 지름길은 없다.

**여섯 가지 명명된 워크플로우.** 기본, TDD, 적대적, 설계, 가설, BDD — 각각 다른 종류의 작업에 맞게 조정된 서로 다른 hat 시퀀스를 가진다. `/quick tdd`는 테스트 우선으로 실행된다. `/quick adversarial`은 회의적인 리뷰어를 추가한다. `/quick design`은 설계 고려 사항을 포함한다. 워크플로우가 규율을 형성하고, 그 규율은 작업 크기에 관계없이 완전한 강도로 실행된다.

결과적으로: 과거에 모든 품질 인프라를 우회하던 작업이 이제 다중 Unit 기능 빌드와 동일한 hat 기반 워크플로우를 거친다. 단지 인메모리에서, 한 번의 Pass로 실행되고, 스스로 정리할 뿐이다.

## 자동 조종

스펙트럼의 반대편에서, `/ai-dlc:autopilot <description>`은 단일 명령으로 전체 AI-DLC 라이프사이클을 실행한다. 상세화, 계획, 모든 Unit 실행, PR을 통한 배포까지.

자동 조종은 AHOTL 모드 — 자율적, 루프 위의 인간 — 로 동작한다. 에이전트는 설명과 코드베이스로부터 요구사항을 상세화하고, Unit으로 분해하며, 각 Unit을 완전한 빌더/리뷰어 사이클을 통해 실행하고, 결과를 배포한다. 명확화 질문도 없다. Unit별 수동 승인도 없다. 백프레셔 품질 게이트가 주요 시행 메커니즘이다.

그러나 자동 조종이 완전히 무인은 아니다. 전략적 경계에서 일시 정지한다:

**범위 가드레일.** 상세화 결과가 다섯 개 이상의 Unit을 생성하면 자동 조종은 중단된다. 옵션을 제시한다: 현재 분해로 계속 진행하거나, 수동 실행으로 전환하거나, 더 좁은 범위로 재상세화한다. 다섯 Unit은 자율 실행이 "효율적"에서 "위험"으로 전환되는 임계값이다 — 잘못된 분해의 피해 반경은 비선형적으로 증가한다.

**블로커 에스컬레이션.** Unit이 인간 입력이 필요한 블로커 — 모호한 요구사항, 누락된 의존성, 코드베이스가 답하지 못하는 설계 결정 — 에 부딪히면, 자동 조종은 추측하는 대신 일시 정지하고 이를 표면화한다.

**배포 전 체크포인트.** 자동 조종은 PR 생성 전에 항상 일시 정지한다. 인간은 변경 사항의 전체 범위를 확인하고 배포를 승인한다. 이것이 최종 전략적 경계다: 에이전트가 작업을 수행했지만, 인간이 인계를 승인한다.

설계 원칙은 일시 정지가 인간의 판단이 가장 큰 가치를 더하는 순간에 대응해야 한다는 것이다. 모든 hat 전환마다가 아니다. 모든 Unit 경계마다가 아니다. 잘못되었을 때 비용이 가장 높은 세 가지 순간: 범위, 블로커, 그리고 배포.

## 자율성 스펙트럼

흥미로운 통찰은 이러한 모드가 존재한다는 것이 아니다. 그것들이 규율과 자율성의 관계에 대해 무엇을 증명하는가이다.

| 측면 | 빠른 모드 | 수동 흐름 | 자동 조종 |
|------|----------|----------|----------|
| 작업 크기 | 사소함 (1-2개 파일) | 모두 | 전체 기능 (다중 Unit) |
| 상세화 | 없음 | 완전, 인간 주도 | 완전, 자동 승인 |
| 워크플로우 | 단일 hat 루프 | 전체 라이프사이클, 수동 | 전체 라이프사이클, 자율 |
| 인간 역할 | 라우팅 확인 | 전환 승인 | 전략적 경계 검토 |

빠른 모드는 30초짜리 수정에서도 완전한 hat 규율을 가질 수 있음을 증명한다. 플래너/빌더/리뷰어 사이클은 작은 작업에서 건너뛰어야 할 오버헤드가 아니다 — 무엇에든 실행할 수 있을 만큼 가볍다. 하네스가 처리할 때 규율의 비용은 0에 가까워진다.

자동 조종은 완전히 자율적인 빌드에서도 전략적 인간 판단을 가질 수 있음을 증명한다. "인간이 모든 것을 승인"과 "인간이 아무것도 승인하지 않음" 사이에서 선택할 필요가 없다. 시스템은 인간 입력이 가장 중요한 세 가지 순간을 식별하고 감독을 그곳에 집중시킨다.

이것들은 반대가 아니다. 동일한 원칙 — 규율과 자율성은 대립하는 힘이 아니라 직교하는 축이다 — 이 서로 다른 규모에 적용된 것이다. 빠른 모드는 최소 규모에서 규율을 극대화한다. 자동 조종은 전체 규모에서 자율성을 극대화한다. 둘 다 중요한 품질 속성을 유지한다: hat 기반 역할 분리, 백프레셔 시행, 그리고 구조화된 검토.

## 실제 조절 장치

다크 팩토리 포스트는 철학적 논증이었다. 빠른 모드와 자동 조종은 그것을 구체화한다.

개발자의 월요일은 이런 모습일 수 있다: 오전에 `/quick tdd fix the flaky test`. 스탠드업 후 새 API 엔드포인트를 `/elaborate`하고, 도메인이 낯설기 때문에 면밀한 검토와 함께 각 Unit을 `/execute`. 점심 후 `/autopilot add pagination to the list endpoints` — 패턴이 잘 확립되어 있고 테스트 커버리지가 충분하기 때문이다.

동일한 도구. 동일한 hats. 동일한 백프레셔. 동일한 품질 게이트. 아키텍처가 아닌 작업에 따라 선택된, 자율성 조절 장치의 세 가지 다른 위치.

스펙트럼은 더 이상 이론이 아니다. 출시되었다.
