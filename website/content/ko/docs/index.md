AI-DLC는 [H•AI•K•U 메서드](https://haikumethod.ai)(Human AI Knowledge Unification)의 소프트웨어 개발 프로파일입니다. AI 어시스턴트와 함께하는 구조적이고 반복적인 소프트웨어 개발을 위한 프레임워크를 제공하며, 명확한 단계와 책임을 갖춘 집중적인 Unit으로 작업을 구성합니다.

## AI-DLC를 사용하는 이유

소프트웨어 개발은 근본적인 변화를 맞이했습니다. AI는 단순한 코드 자동완성을 넘어 지속적인 자율 추론으로 진화했으며, 몇 초 만에 반복 작업을 수행하고, 수 시간에 걸친 워크플로우에서 컨텍스트를 유지하며, 프로덕션 코드를 대규모로 작성합니다.

워터폴, 애자일, 스크럼과 같은 전통적인 방법론은 긴 반복 주기를 가진 인간 중심 프로세스를 위해 설계되었습니다. 순차적인 단계, 인수인계 문서, 승인 게이트는 요구사항 변경이 몇 주간의 재작업을 의미하던 시절에는 합리적이었습니다. 하지만 AI와 함께라면 이러한 단계들은 지속적인 흐름으로 통합됩니다. 기존 방법론에 AI를 억지로 끼워 맞추는 것은 AI의 잠재력을 제한할 뿐입니다.

AI-DLC는 이 새로운 현실을 위해 제1원칙부터 새롭게 설계되었습니다.

## 핵심 원칙

### 1. Hats가 집중력을 이끈다

AI-DLC는 hats를 사용하여 작업 모드 간의 명시적인 전환을 표시합니다 — Planner, Builder, Reviewer. Hat을 전환하면 사용자와 AI 모두 집중 방향과 기대치가 변경되었음을 인식합니다.

### 2. 집중된 작업 Unit

작업은 Unit으로 구성됩니다 — 명확한 성공 기준을 가진 집중적인 기능 단위입니다. 각 Unit은 한 세션 내에 완료할 수 있을 만큼 작으면서도 가치를 제공할 수 있을 만큼 의미 있습니다.

### 3. 역압을 통한 품질 확보

AI-DLC는 구축 방법을 규정하는 대신, 반드시 충족해야 할 제약 조건을 정의합니다 — 테스트 통과, 타입 검사, 린팅 클린. AI는 모든 게이트가 통과될 때까지 반복합니다. 리뷰는 나중에 덧붙이는 것이 아니라 사이클에 내장되어 있습니다.

### 4. 측정 가능한 진행 상황

작업이 명확한 기준을 가진 Unit으로 구성되기 때문에 진행 상황은 항상 측정 가능합니다. 현재 위치와 남은 작업을 정확히 파악할 수 있습니다.

## 시작하기

1. Claude Code 프로젝트에 AI-DLC 플러그인 설치
2. 명확한 성공 기준과 함께 첫 번째 Intent 정의
3. 핵심 hats를 순서대로 진행: Planner → Builder → Reviewer
4. Unit을 완료하고 다음 Unit으로 이동
5. 구축 완료 후 `/ai-dlc:operate`로 지속적인 운영 관리

자세한 지침은 [빠른 시작](/docs/quick-start/) 가이드를 참조하세요.
