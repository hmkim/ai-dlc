# Cowork 모드

Cowork 모드를 사용하면 git 저장소 내부에 있지 않을 때도 AI-DLC를 활용할 수 있습니다. 예를 들어, 오케스트레이터가 여러 저장소에 걸쳐 작업을 조율하거나, 팀/cowork Claude 세션에서 작업하는 경우가 이에 해당합니다.

## 동작 방식

git 저장소 외부에서 `/ai-dlc:elaborate`를 실행하면, AI-DLC가 이를 감지하고 cowork 모드로 진입합니다:

1. **저장소 URL 확인** — AI-DLC가 작업 대상 저장소를 묻습니다. VCS MCP 도구(예: GitHub MCP)를 사용할 수 있는 경우, 검색된 저장소를 선택지로 제시합니다.
2. **저장소 클론** — 저장소가 임시 워크스페이스에 클론됩니다.
3. **정상 진행** — 클론이 완료되면 로컬 저장소에서 작업하는 것과 동일하게 모든 기능이 동작합니다. 설정, 프로바이더, 훅, 그 외 모든 기능이 예상대로 작동합니다.

핵심 원칙: **클론을 통해 cowork 문제 영역이 완전히 해소됩니다**. 초기 클론 이후에는 별도의 cowork 전용 코드 경로가 존재하지 않습니다.

## 아티팩트 전달

Cowork 모드에서 elaboration이 `.ai-dlc/` 아티팩트를 작성하고 티켓을 생성한 후:

- 아티팩트는 intent 브랜치에 커밋됩니다 (일반 방식과 동일)
- intent 브랜치는 자동으로 원격 저장소에 푸시됩니다
- 빌더는 해당 브랜치를 pull하거나 독립적으로 클론할 수 있습니다

## Cowork에서의 실행

`/ai-dlc:execute` 스킬은 cowork를 투명하게 처리합니다:

- intent 브랜치에 원격 트래킹이 구성되어 있는지 확인합니다
- 각 unit을 시작하기 전에 최신 변경 사항을 pull합니다
- 빌더 팀원을 생성할 때 저장소 URL을 포함하여 독립적으로 클론할 수 있도록 합니다

## Cowork 사용 시나리오

- **팀 오케스트레이션** — 리드가 단일 세션에서 여러 저장소에 걸친 작업을 조율하는 경우
- **원격 플래닝** — 아직 클론하지 않은 저장소에 대해 elaborate하는 경우
- **CI/CD 통합** — AI-DLC 워크플로우를 실행해야 하는 자동화 시스템
