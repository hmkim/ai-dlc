이 체크리스트는 전체 팀을 AI-DLC에 온보딩하는 과정을 안내합니다. 테크 리드와 엔지니어링 매니저를 위해 설계되었습니다.

## 사전 요건

팀 온보딩을 시작하기 전에:

### 챔피언 준비 상태
- [ ] 챔피언 지정 완료 (숙련된 AI-DLC 사용자)
- [ ] 챔피언이 개인적으로 5개 이상의 Unit 완료
- [ ] 챔피언이 여러 워크플로우 유형 사용 경험 보유
- [ ] 챔피언이 일반적인 질문에 답변 가능
- [ ] 챔피언에게 팀 지원을 위한 시간 배정 완료

### 팀 준비 상태
- [ ] 모든 팀원이 Claude Code 접근 권한 보유
- [ ] 팀에 학습 곡선을 소화할 여유 있음 (크런치 기간 아님)
- [ ] 경영진이 도입을 지지
- [ ] 팀이 AI-DLC 도입 예정을 인지

### 프로젝트 준비 상태
- [ ] 팀 도입을 위한 첫 번째 프로젝트 선정
- [ ] 프로젝트가 저위험 수준 (크리티컬 패스 아님)
- [ ] 프로젝트 요구사항이 명확
- [ ] 프로젝트 규모가 적절 (2~4 스프린트)

## 1단계: 설정 (도입 전)

### 문서 준비
- [ ] AI-DLC 문서 팀 공유 완료
- [ ] 팀 컨벤션 문서 초안 작성
- [ ] 예시 Intent 준비 (팀 도메인 기반)
- [ ] FAQ 문서 준비 (예상 질문 반영)

### 도구 설정
- [ ] 모든 팀원이 플러그인 설치 가능
- [ ] 팀 특화 설정 사항 문서화
- [ ] AI-DLC 질문을 위한 Slack 채널 또는 커뮤니케이션 채널 개설

### 일정 수립
- [ ] 팀 소개 세션 일정 확정 (60~90분)
- [ ] 각 팀원과의 페어 프로그래밍 세션 일정 확정
- [ ] 체크인 미팅 일정 확정 (첫 스프린트 동안 주 1회)

---

## 2단계: 팀 소개

### 소개 세션

**진행 순서 (60분):**

- [ ] **AI-DLC 도입 이유** (10분)
  - [ ] 문제 정의 설명
  - [ ] 기대 효과 설명
  - [ ] 팀 업무와의 연관성 명확히 전달

- [ ] **라이브 데모** (20분)
  - [ ] 챔피언이 전체 흐름 시연
  - [ ] 팀 도메인의 실제 예시 활용
  - [ ] 네 가지 hats 모두 시연

- [ ] **Q&A** (20분)
  - [ ] 질문 답변
  - [ ] 우려 사항 수용
  - [ ] 회의적인 의견 존중하며 대응

- [ ] **다음 단계** (10분)
  - [ ] 페어 프로그래밍 일정 공유
  - [ ] 첫 번째 프로젝트 확정
  - [ ] 지원 리소스 안내

### 소개 세션 이후
- [ ] 녹화본 공유 (해당하는 경우)
- [ ] 문서 링크 전송
- [ ] 세션 중 나온 질문에 대한 서면 답변
- [ ] 페어 프로그래밍 일정 최종 확인

---

## 3단계: 페어 프로그래밍

각 팀원별로:

### 세션 준비
- [ ] 페어 세션용 작업 선정
- [ ] 작업 규모 적절 (1~2시간)
- [ ] 챔피언이 컨텍스트 준비 완료
- [ ] 팀원의 개발 환경 준비 완료

### 세션 진행 중
- [ ] 챔피언이 먼저 진행, 팀원이 관찰
- [ ] 각 hat 전환 시 설명
- [ ] 주요 의사결정 순간 짚어주기
- [ ] 질문이 생기는 즉시 답변

- [ ] 역할 전환 - 팀원이 진행
- [ ] 챔피언이 필요 시 안내 제공
- [ ] 팀원이 스스로 결정하도록 유도
- [ ] 방향이 어긋날 때 부드럽게 수정

### 세션 이후
- [ ] 디브리핑: 잘 된 점은? 헷갈렸던 점은?
- [ ] 필요 시 후속 세션 일정 확정
- [ ] 팀원의 다음 단계 명확히 정리

## 4단계: 독립 수행

### 독립 수행 역량 확립

각 팀원의 첫 번째 독립 Unit에 대해:

- [ ] 작업 배정
- [ ] 팀원이 독립적으로 시작
- [ ] 챔피언은 대기 중이나 직접 관여하지 않음
- [ ] 팀원이 첫 번째 Unit 완료
- [ ] 챔피언이 완료된 Unit 검토

### 첫 스프린트 체크포인트

**첫 번째 주 종료 시:**
- [ ] 모든 팀원이 독립 Unit 최소 1개 완료
- [ ] 공통 질문 사항 문서화
- [ ] 주요 블로커 없음

**첫 번째 스프린트 종료 시:**
- [ ] 팀이 AI-DLC를 일관되게 사용 중
- [ ] 컨벤션 준수 중
- [ ] 품질 지표 기준선 수립

### 지원 체계
- [ ] Slack 채널에서 질문 활발히 진행 중
- [ ] 챔피언이 정기적으로 체크인 수행
- [ ] 주간 팀 싱크에 AI-DLC 논의 포함
- [ ] 개선을 위한 이슈 문서화 진행 중

## 6단계: 통합

### 프로세스 통합

**데일리 스탠드업:**
- [ ] Unit 상태를 포함하도록 형식 업데이트
- [ ] 예시: "unit-02 작업 중, Builder hat, 블로커 없음"
- [ ] 팀이 새 형식 사용 중

**스프린트 플래닝:**
- [ ] 플래닝 중 기능을 Intent 단위로 분해
- [ ] 스토리 포인트를 Unit 추정으로 대체/보완
- [ ] 플래닝에서 의존성 파악

**풀 리퀘스트:**
- [ ] PR 템플릿에 Intent/Unit 참조 포함
- [ ] 리뷰어가 기준 충족 여부 확인
- [ ] PR 설명에 Unit 파일 링크 포함

**회고:**
- [ ] 회고에서 AI-DLC 논의
- [ ] 피드백 수집 중
- [ ] 개선 사항 반영 중

### 도구 통합 (해당하는 경우)
- [ ] CI/CD가 품질 게이트 인식
- [ ] 대시보드에서 Unit 완료 현황 추적
- [ ] 지표 수집 자동화

## 8단계: 지원

### 지속적인 지원 체계

- [ ] 챔피언의 지속적인 지원 가능 상태 유지
- [ ] 오피스 아워 일정 확정 (주 1회 또는 격주)
- [ ] 문서 최신 상태 유지
- [ ] 새로운 학습 내용 팀과 공유

### 이슈 처리

**공통 이슈 체크리스트:**
- [ ] "오버헤드가 너무 많다" → 컨벤션 검토, 가능한 부분 간소화
- [ ] "기준이 불명확하다" → 기준 작성 워크숍 진행
- [ ] "Hat 전환이 어색하다" → 추가 연습, 페어 세션 진행
- [ ] "품질이 개선되지 않는다" → 게이트 적용 방식 검토

### 에스컬레이션 경로
- [ ] 대부분의 질문은 챔피언이 처리
- [ ] 프로세스 이슈는 테크 리드가 처리
- [ ] 리소스/우선순위 이슈는 매니저가 처리
- [ ] 난해한 문제는 외부 커뮤니티 활용

## 성공 기준

### 단계별 완료 체크리스트

**1~2단계 (설정 및 소개) 완료:**
- [ ] 모든 팀원이 소개 세션 참석
- [ ] 모든 팀원이 문서에 접근 가능
- [ ] 페어 세션 일정 확정

**3~4단계 (교육 및 독립 수행) 완료:**
- [ ] 모든 팀원이 페어 세션 완료
- [ ] 모든 팀원이 독립 Unit 완료
- [ ] 지원 체계 정상 작동

**5~6단계 (컨벤션 및 통합) 완료:**
- [ ] 컨벤션 문서화 및 준수
- [ ] 프로세스 통합 완료
- [ ] 팀이 AI-DLC를 일관되게 사용 중

**7~8단계 (지표 및 지원) 완료:**
- [ ] 지표가 긍정적 또는 중립적 영향 확인
- [ ] 지원 체계가 지속 가능
- [ ] 팀이 독립적으로 운영 중

### 팀 온보딩 완료 조건:

- [ ] 팀원 100%가 독립 Unit 최소 3개 완료
- [ ] 팀 컨벤션 문서화 및 준수
- [ ] AI-DLC가 일상 프로세스에 통합
- [ ] 품질 지표 유지 또는 개선
- [ ] 긍정적인 개발자 피드백 (70% 이상)
- [ ] 챔피언 지원 없이 일상적 운영 가능
