이 체크리스트는 AI-DLC를 사용하여 첫 번째 intent를 완료하는 과정을 안내합니다. 각 섹션을 순서대로 따라가세요.

## 시작하기 전에

첫 번째 intent를 시작하기 전에 다음 단계를 완료하세요:

### 환경 설정
- [ ] Claude Code 설치 및 정상 작동 확인
- [ ] AI-DLC 플러그인 설치 (`/plugin marketplace add thebushidocollective/ai-dlc` 실행 후 `/plugin install ai-dlc@thebushidocollective-ai-dlc --scope project`)
- [ ] 플러그인 활성화 확인 (`/ai-dlc:elaborate` 등의 명령어가 인식되는지 확인)

### 프로젝트 선택
- [ ] 실제 프로젝트 선택 (연습용 토이 프로젝트 제외)
- [ ] 명확한 목표가 있는 프로젝트 (무엇을 만들지 알고 있는 상태)
- [ ] 시간적 여유가 있는 상황 (학습할 여유 확보)
- [ ] 코드베이스에 익숙한 상태 (한 번에 하나씩 새로운 것을 익히기 위해)

### 마음가짐 준비
- [ ] 집중할 수 있는 2~4시간 확보
- [ ] 느리게 느껴지더라도 프로세스를 따를 준비
- [ ] 최소 하나의 완전한 Unit을 완료할 의지

---

## 1단계: 구체화 (Elaboration)

`/ai-dlc:elaborate`를 사용하여 Claude와 협력하여 intent를 정의합니다.

### 구체화 시작
- [ ] `/ai-dlc:elaborate` 실행
- [ ] 만들고자 하는 것을 2~3문장으로 설명

### Intent 정의
- [ ] Claude의 명확화 질문 검토
- [ ] 범위, 제약 조건, 요구사항에 관한 질문에 답변
- [ ] 설명이 명확해질 때까지 내용 다듬기

### 완료 기준 작성
- [ ] 제안된 완료 기준 검토
- [ ] 각 기준이 다음을 충족하는지 확인:
  - [ ] 구체적 (모호하지 않을 것)
  - [ ] 측정 가능 (검증할 수 있을 것)
  - [ ] 원자적 (하나의 사항만 테스트할 것)
- [ ] 누락된 기준 추가
- [ ] 범위를 벗어난 기준 제거

### Unit 정의
- [ ] 제안된 Unit 분류 검토
- [ ] Unit이 다음 조건을 충족하는지 확인:
  - [ ] 응집성 (관련 스토리가 함께 묶여 있을 것)
  - [ ] 느슨한 결합 (Unit 간 의존성 최소화)
  - [ ] 독립적 완료 가능 (각 Unit을 독립적으로 완료하고 테스트할 수 있을 것)
- [ ] 필요 시 Unit 경계 조정
- [ ] Unit 순서 및 의존성 확인

### 산출물 확인
- [ ] 전체 설명이 포함된 `intent.md` 생성 확인
- [ ] `unit-01-*.md` (및 이후 Unit 파일) 생성 확인
- [ ] 각 Unit 파일에 다음 항목 포함 여부 확인:
  - [ ] 설명
  - [ ] 완료 기준
  - [ ] 의존성 (있는 경우)

### 구체화 완료
- [ ] Intent가 명확하고 잘 정의된 상태
- [ ] Unit의 범위가 적절하게 설정된 상태
- [ ] 실행 시작 준비 완료

## 2단계: 첫 번째 Unit

`/ai-dlc:execute`를 사용하여 첫 번째 Unit을 진행합니다.

### 실행 시작
- [ ] `/ai-dlc:execute` 실행
- [ ] Claude가 올바른 Unit을 로드했는지 확인

### Planner Hat

- [ ] Claude가 접근 방식 제안
- [ ] 다음 항목에 대해 계획 검토:
  - [ ] 기술적 실현 가능성
  - [ ] 모든 기준의 포괄 여부
  - [ ] 적절한 범위
- [ ] 필요 시 명확화 질문
- [ ] 계획 승인 (또는 수정 요청)

### Builder Hat

- [ ] Claude가 구현 시작
- [ ] 진행 상황 모니터링 (기본적으로 OHOTL 모드)
- [ ] 방향이 벗어날 경우 수정 지시
- [ ] Claude가 질문할 경우 답변 제공

**품질 게이트 확인:**
- [ ] 새로운 기능에 대한 테스트 작성
- [ ] TypeScript/린트 오류 미발생
- [ ] 프로젝트 컨벤션 준수

### Reviewer Hat

- [ ] Claude가 자체 검토 수행
- [ ] 완료 기준 상태 검토:

```markdown
## Completion Criteria Status
- [x] Criterion 1 - verified by [method]
- [x] Criterion 2 - verified by [method]
- [ ] Criterion 3 - FAILED: [reason]
```

- [ ] 기준 미충족 시:
  - [ ] Claude가 수정 방안 제안
  - [ ] Builder로 돌아가 수정 구현
  - [ ] 모든 기준이 통과될 때까지 재검토

### 첫 번째 Unit 완료

- [ ] 모든 완료 기준 충족
- [ ] 품질 게이트 통과 (테스트, 타입, 린트)
- [ ] Unit 파일 상태 업데이트: `complete`
- [ ] Unit 참조와 함께 변경사항 커밋
- [ ] 다음 Unit 또는 intent 완료 준비

---

## 3단계: 반복 (Iteration)

나머지 Unit을 계속 진행합니다.

### 각 나머지 Unit에 대해

- [ ] `/ai-dlc:execute` 실행하여 다음 Unit 로드
- [ ] 의존성이 충족되었는지 확인
- [ ] Planner → Builder → Reviewer 사이클 완료
- [ ] Unit 참조와 함께 커밋
- [ ] Unit 상태 업데이트

### Unit 사이에

- [ ] 컨텍스트가 과도하게 쌓이고 있는지 확인
- [ ] 필요 시 `/clear` 실행 후 `/ai-dlc:execute`로 계속 진행
- [ ] 커밋된 산출물이 현재 상태를 반영하는지 확인

### 블로커 처리

Unit 진행 중 블로커가 발생한 경우:

- [ ] Unit 파일에 블로커 기록
- [ ] 분류: 기술적 / 요구사항 / 외부 요인
- [ ] 결정: 우회 가능 / 도움 필요 / Unit 차단
- [ ] 차단 시: 다음 가능한 Unit으로 이동
- [ ] 우회 가능 시: 가정 사항 기록 후 계속 진행

---

## 4단계: 완료 (Completion)

Intent를 마무리합니다.

### 최종 검토

- [ ] 모든 Unit이 완료 상태로 표시됨
- [ ] `intent.md`의 전체 기준 충족
- [ ] 모든 Unit에 걸쳐 품질 게이트 통과
- [ ] 미해결 블로커 없음

### 문서화

- [ ] 필요 시 README 업데이트
- [ ] API 문서 최신화 (해당하는 경우)
- [ ] 새로운 패턴 문서화

### 커밋 및 PR

- [ ] 완료 메시지와 함께 최종 커밋
- [ ] PR 생성 (해당하는 경우)
- [ ] PR 설명에 intent 및 Unit 참조 포함
- [ ] 팀 리뷰 준비 완료

### 정리

- [ ] 임시/디버그 코드 제거
- [ ] console.log/디버그 구문이 남아 있지 않은지 확인
- [ ] 임시 파일 정리

---

## 5단계: 회고 (Reflection)

경험을 통해 배웁니다.

### 자기 평가

다음 질문에 솔직하게 답하세요:

**프로세스:**
- [ ] hat 전환이 자연스럽게 느껴졌나요?
- [ ] 자신의 hat을 유지했나요, 아니면 벗어났나요?
- [ ] Researcher 단계가 유익했나요?
- [ ] Review 단계에서 문제가 발견되었나요?

**기준 품질:**
- [ ] 기준이 충분히 구체적이었나요?
- [ ] 돌이켜보면 불명확했던 기준이 있었나요?
- [ ] 누락된 중요한 기준이 있었나요?

**도구 사용:**
- [ ] 명령어 사용 시 불편한 점이 있었나요?
- [ ] `/clear` + `/ai-dlc:execute`가 원활하게 작동했나요?
- [ ] 산출물이 도움이 되었나요?

### 기록할 지표

향후 비교를 위해 기록하세요:
- Intent 완료 소요 시간: ____
- Unit 수: ____
- 블로커 발생 횟수: ____
- 작업 중 기준 변경 횟수: ____

### 다음을 위한 개선 사항

이번 경험을 바탕으로:
- [ ] 다음에는 무엇을 다르게 하겠나요?
- [ ] 반복할 만큼 잘 된 점은 무엇인가요?
- [ ] 확립할 컨벤션이 있나요?

## 빠른 참조

### 명령어
| 명령어 | 사용 시점 |
|---------|-------------|
| `/ai-dlc:elaborate` | 새 intent 시작 |
| `/ai-dlc:execute` | Unit 작업 계속/시작 |
| `/researcher` | 더 깊은 이해가 필요할 때 |
| `/planner` | 접근 방식을 재설계해야 할 때 |
| `/builder` | 구현 준비가 되었을 때 |
| `/reviewer` | 검증 준비가 되었을 때 |
| `/clear` | 컨텍스트가 과도하게 쌓였을 때 |

### 기준 체크리스트
- [ ] 구체적 (모호하지 않을 것)
- [ ] 측정 가능 (검증할 수 있을 것)
- [ ] 원자적 (하나의 사항)
- [ ] 긍정적 케이스 포함
- [ ] 부정적 케이스 포함
- [ ] 엣지 케이스 포함
- [ ] 품질 게이트 포함

### Hat 흐름
```
Researcher → Planner → Builder → Reviewer → Next Unit
     ↑           ↑         ↓         ↓
     └───────────┴─────────┘         │
           (when needed)             │
                                     ↓
                               Unit Complete
```

## 축하합니다!

첫 번째 AI-DLC intent를 완료했습니다. 이 과정이 "그냥 코딩하는 것"보다 느리게 느껴졌을 수 있지만, 다음을 생각해 보세요:

- 버그가 되기 전에 얼마나 많은 문제가 사전에 발견되었나요?
- 무엇을 만들었는지에 대한 문서가 얼마나 명확한가요?
- 다른 사람이 이 작업을 이해하기가 얼마나 쉬울까요?

다음 intent는 더 빠르게 진행될 것입니다. 다섯 번째 intent쯤 되면 이 과정이 자연스럽게 느껴질 것입니다.
